# 03 · 大模型效果评测与 Badcase 归因

**看板：** 打开 [`index.html`](index.html)（读取 report.json 渲染，数据全部来自真实调用）

## 设计

- **10 条用例**：政策可答 4 / 否定条款 1 / 订单查询 2 / 应拒答 2 / 陷阱（假命中）1
- **4 条打分规则**，每条 25 分制权重，共 100 分：
  1. **事实一致**（30）：回答中出现的每个数字都必须能在证据源里找到，找不到即编造
  2. **拒答正确**（25）：该拒的必须拒，不该拒的不许乱拒（双向判定）
  3. **格式合规**（20）：≤200 字、无 markdown、无"作为一个 AI"式元话术
  4. **可执行**（25）：必须给出具体下一步（入口/时限/转人工）

## 实测：规则迭代三轮，20 条回答交叉验证

回答由模型真实生成（两批独立运行，各 10 条）。**规则是确定性的，对同一批回答重算不同版本的规则，分数差异全部来自规则本身**——这是本项目的核心方法。

| 规则版本 | 平均分（20 条） | 满分条数 | 修了什么 |
|---|---|---|---|
| v1 | 83.5 | 10/20 | 初版：证据池只有知识库 |
| v2 | 92.5 | 14/20 | **修掉一个评测器自己的 bug**：把引用订单数据（金额/日期/状态）的正确回答判成"编造"，因为证据池漏了订单库 |
| v3 | **98.8** | 19/20 | 修掉第二个误判："如订单已超 30 天，我这边无法…"这类条件式说明被整段匹配判成拒答，改为只看第一句主结论 |

- 第一批（b1）：v1 86 分 → v2 95 分
- 第二批（b2，全新回答验证，防止在第一批上过拟合）：v1 81 分 → v2 90 分 → v3 **100 分（10/10）**

剩余 1 条失分是"可执行"规则词表不全（回答写了"请下单时选择支付方式"但没命中动作词表）。**故意不修**：在 20 条上无限调规则就是在过拟合评测集，这条留给更大样本验证。

## 为什么不用模型自评

让模型给自己的回答打分，等于用感觉验证感觉。本项目所有判定（数字是否可追溯、是否拒答、格式、可执行）都是字符串/规则计算，任何人跑 `node run.mjs` 都能复现同样的分数。

## 运行

```bash
node run.mjs               # 生成一批新回答并打分（写入 batch-<TAG>.json）
TAG=b2 node run.mjs        # 第二批
node compare.mjs           # 合并批次、交叉重算三版规则 → report.json
```
