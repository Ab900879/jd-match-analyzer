# 一个客服 Agent，四个零件各值多少分

> 2026-11-03 ｜ 20 条用例 × 4 组对照，共 104 次真实调用
> 目的不是证明我的东西好，是搞清楚**哪一块在起作用，代价是多少**。

---

## 一、为什么要做这个实验

原来的说法是："20 条测试命中率从 85% 到 100%。"

这句话回答不了三个问题：

- 85% 是什么水平？**没有基线。**
- 提升是靠提示词、知识库，还是工具调用？**不知道。**
- 全套跑一次多少钱、多慢？**没算过。**

所以拆成四组，把每个零件单独拎出来称一遍。

## 二、实验设计

同一批 20 条用例、同一个模型（deepseek-v4-flash）、同一时段、thinking 全关。

| 组 | 给了什么 | 在回答什么 |
|---|---|---|
| **A 裸调** | 一句"你是电商客服" | 模型本身能干多少（基线） |
| **B 仅提示词** | A + 三条铁律（不编造、说不清就转人工、给具体数字） | 光靠 prompt 值多少 |
| **C 仅知识库** | 朴素提示词 + 检索到的条款直接塞进上下文 | 光靠知识库值多少 |
| **D 完整版** | ReAct 循环 + 3 个工具 + 三条铁律（线上跑的就是这个） | 合起来多少 |

**20 条用例分四类**：政策可答 8、需查订单 5、超范围应拒答 4、陷阱 3。

**判定全部由规则完成，不让模型自评。** 每条的期望值事先写死：该拒的必须拒、该答的必须包含关键事实（"7 天""12 元""199"这种）。工具调用是单独一列检查。

**两种口径分开算**，因为混在一起会冤枉人：

- **答案口径**：只看答得对不对
- **全口径**：加上"该调的工具调了没有"

A/B/C 三组压根没有工具，用全口径算它们等于让它们自带枷锁。所以主结论看答案口径，全口径只列出来做参照。

**另外剔掉 2 条无效用例**（#13、#19）：这两条没写死期望答案，任何组都能"通过"。分母从 20 变成 18。

## 三、四组结果

| 组 | 答案口径 | 全口径 | 平均延迟 | 每条花费 | 值多少 |
|---|---|---|---|---|---|
| A 裸调 | **6/18 = 33%** | 1/20 | 2.6s | ¥0.0010 | 基线 |
| B 仅提示词 | **6/18 = 33%** | 2/20 | 1.9s | ¥0.0006 | **+0** |
| C 仅知识库 | **10/18 = 56%** | 0/20 | 2.1s | ¥0.0004 | +22 个百分点 |
| D 完整版 | **17/18 = 94%** | 19/20 | 4.1s | ¥0.0037 | +39 个百分点 |

- 提示词贡献：**0**
- 知识库贡献：**+4 条**
- 工具 + ReAct 贡献：**+7 条**
- 完整版 vs 裸调：**+11 条 = +61 个百分点**
- 完整版比裸调贵 **3.7 倍**，比单纯知识库贵 **9 倍**，慢 **1.6 倍**

四组一共 104 次调用、31,669 输入 token、6,308 输出 token，合计不到两毛钱。

## 四、三个反直觉的结论

### 1. 加了提示词，总分一点没涨——但错的类型全换了

A 和 B 都是 33%。看总分就是"提示词没用"。但把通过的题目对一下：

| | 通过的题 |
|---|---|
| A 裸调 | 1,3,4,5,6,13,19,20 |
| B 仅提示词 | 1,2,13,14,15,18,19,20 |

**只有 1、13、19、20 是重合的。**

- A 组能答对政策常识题（7 天无理由、48 小时发货这类模型本来就知道的），但**该拒的不拒**——问它 A9999 订单到哪了，它会编一段物流状态出来。
- B 组被三条铁律管住了，不敢编，**但也不敢答**——问它优惠券能不能叠加，它说"以页面为准，建议咨询客服"。

所以这两种错是反的：

> **裸调是"敢答、答错"，加提示词是"不敢答、答不全"。**
> 前一种在客服场景里是合规风险（编政策条款），后一种是转化损失（用户问什么都得不到答案）。

只看总分会把这两种错当成同一种，然后得出"提示词没用"的结论——**这个结论是错的，它只是把风险从一种换成了另一种。**

### 2. 知识库是唯一真增益，但它的真实召回率只有 35%

第 1 条用例："买的东西不想要了，几天内能退？"

这条在 C 组和 D 组都答对了。但我查了检索记录：**检索返回 0 条**。

它答对是因为模型自己知道"7 天无理由退货"这条常识。**分数是模型挣的，不是知识库挣的。**

再往下查，问题更严重：

| 问法 | 检索命中率 |
|---|---|
| 照抄知识库关键词的问法（"无理由退货""几天内能退"） | **88%** |
| 换成用户真实说法（"东西不想要了还能退吗""什么时候能寄出来"） | **35%** |

我原来的 20 条测试，题目是我自己照着知识库关键词写的。**这是开卷考试。**

真实用户不会说"无理由退货"，他说"我不想要了"。这一句里没有"退货"两个字，关键词匹配就漏了。

### 3. 完整版多花的钱，买的是"不该拒的别拒"

D 组比 C 组多 7 条，其中 5 条是订单查询——C 组没有工具，压根查不了订单。剩下的差距在**拒答的分寸**上：C 组看不见订单、也不知道该不该转人工，只能凭上下文猜。

代价是每条从 ¥0.0004 涨到 ¥0.0037。**贵 9 倍。**

值不值取决于错一条的代价：客服说错一条政策可能引来投诉甚至赔付，那 9 倍很便宜。如果换成闲聊机器人，这 9 倍全是浪费。

**这个判断 AI 给不了，得看业务。**

## 五、压边界：三种极端情况

### 规模：库从 10 条扩到 99 条，命中率纹丝不动（88%）

一开始我觉得是好事，细看不是。

因为它是关键词硬匹配，干扰条目（运费险、价格保护、预售定金…）跟测试问题没有词面重叠，所以扩库不影响它。**它不敏感的原因不是它稳，是它笨**——换成同义说法就漏，加多少条都一样。

### 库外问题：5 条全对，一个都没编

问它有没有实体店、能不能开专票、会员等级怎么升、双十一什么活动、公司叫什么名字——**5 条全部正确转人工，零编造。**

这是三条铁律里"查不到就拒答"真的生效了。

### 污染：往库里塞错误条款，四版都没被带跑

| 污染方式 | 结果 |
|---|---|
| 新增一条"30 天无理由退货"（与原文冲突） | 两条条款撞车 → 判为无法确认 → 转人工 |
| 把原文直接改成 30 天 | 同上，转人工 |
| 库里只剩这一条错的 | 还是转人工 |
| 改成"优惠券可叠加 3 张"（模型没有常识的规则） | 转人工 |

**没被带跑，但代价是"本来能答的也不答了"。** 而且我要说清楚一点：它扛住靠的不完全是我的设计——模型自己觉得"30 天无理由"不对劲。换成一条它没有常识的错误（比如某型号的保修期），大概率就照抄了。

**我没能证明它一定不会被污染带跑，我只证明了这四版没带跑。**

## 六、因此改了什么

| 发现 | 动作 |
|---|---|
| 提示词把"编造"换成了"过度拒答" | 提示词里加一条：**能答的必须答，答不了才转人工**。以后评测要分两个指标——编造率、过度拒答率，不能只看总分 |
| 检索真实召回只有 35% | 测试集加一组"用户说法"版本，关键词问法和自然问法都要跑。检索层要加同义词扩展，光靠关键词不行 |
| 第 1 条是蒙对的 | 评测必须记录"答对时有没有真的查到证据"，否则分不清是知识库的功劳还是模型的常识 |
| 用例 #13、#19 没有期望答案 | 补上期望值，或者直接删掉。没有期望值的用例等于白送分 |
| 判定器把"边答边兜底"误判成拒答 | 拒答判定改成：第一句给了具体事实、且没有否定表述的，算作答。已重判 1 条（D 组 #1），分数 89%→94% |

## 七、这次最该被记住的一句话

> 我原来那个"95% 命中率"，是拿我照着自己知识库关键词写的题目考出来的。
> 换成用户真会说的话，检索只找到三分之一。
> **所以问题不在模型会不会答，在它压根没查到。**
