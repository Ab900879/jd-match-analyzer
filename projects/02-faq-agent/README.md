# 02 · AI Agent 工具调用与 FAQ 知识库

> 一句话：客服机器人，查不到就转人工，不猜。**并且我把四个零件的贡献拆开称过了。**

ReAct 模式的客服 Agent：3 个工具、查不到就拒答、20 条自动化测试 + 四组对照实验。

**在线演示：** 打开 [`index.html`](index.html)（左边聊机器人，右边一键跑 20 条测试）
**实验报告：** [`report.md`](report.md)（20 条用例 × 4 组，104 次真实调用）

---

## 先说结论

一开始我写的是"20 条测试命中率 95%"。做完对照实验，这句话得改：

| 组 | 给了什么 | 答案正确率 | 每条成本 |
|---|---|---|---|
| A 裸调 | 一句"你是客服" | 6/18 = **33%** | ¥0.0010 |
| B 仅提示词 | A + 三条铁律 | 6/18 = **33%** | ¥0.0006 |
| C 仅知识库 | 朴素提示词 + 检索结果 | 10/18 = **56%** | ¥0.0004 |
| D 完整版 | ReAct + 工具 + 三条铁律 | 17/18 = **94%** | ¥0.0037 |

三件不看数据想不到的事：

**1. 加提示词，总分一点没涨，但错的类型全换了。**
A 和 B 都是 33%，可通过的题目只重合 4 条。裸调是"敢答、答错"（问 A9999 订单，它编一段物流状态）；加铁律后变成"不敢答、答不全"（问优惠券能不能叠加，它说"以页面为准"）。前一种是合规风险，后一种是转化损失——**只看总分会把这两种错当同一种。**

**2. 知识库检索的真实召回率只有 35%。**
我原来那 20 条题，是照着自己知识库的关键词写的。换成用户真会说的话：

| 问法 | 检索命中 |
|---|---|
| "无理由退货的运费谁出" | 88% |
| "寄回去要我自己付钱吗" | **35%** |

第 1 条"买的东西不想要了，几天内能退"——检索返回 0 条，答案却对了，因为模型自己知道 7 天无理由。**那是模型挣的，不是知识库挣的。**

**3. 完整版多花的钱，买的是"不该拒的别拒"。**
比单纯知识库贵 9 倍，换来的是能真查订单、该拒才拒。值不值看业务：客服说错一条政策可能引来投诉，9 倍很便宜；闲聊机器人就全是浪费。

完整推导、逐条数据、三组压边界测试（规模 10→99 条 / 库外 5 问 / 四种污染）都在 [`report.md`](report.md)。

## 设计：先写 PRD，再写代码

PRD 里最重要的一条是**拒答策略**：知识库查不到、订单查不到、问题超出客服范围（议价/竞品/闲聊），必须转人工，禁止猜测。这比"答得多"重要——客服场景里，一句编造的政策造成的损失远大于一句"我帮你转人工"。

| 工具 | 职责 | 输入 |
|---|---|---|
| `search_faq` | 政策知识库检索（9 条） | `{"query": "关键词"}` |
| `query_order` | 订单状态查询（5 条 mock 数据） | `{"order_id": "A1001"}` |
| `handoff_to_human` | 转人工并生成工单号 | `{"reason": "原因"}` |

## 20 条用例与两轮迭代

期望值由人标注（该答/该拒/必须调哪个工具），判定由规则完成，**不让模型自评**。

| 轮次 | 命中率 | 发现的问题 | 处理 |
|---|---|---|---|
| 第一轮 | 17/20 = **85%** | ①"如仍有疑问可转人工"被判成拒答（判定器 bug）②身份问题被过度转人工 | ①拒答判定改为只看第一句主结论 ②Prompt 增加身份类问题处理规则 |
| 第二轮（全量复测） | 18/20 = **90%** | #9 回答"已于 10 月 10 日签收"却因不含逐字"已签收"被判错 | 属于标注过严，修正标注后离线重判（回答不变）→ **19/20 = 95%** |

> **这个 95% 要打折看。** 题目是我照着知识库关键词写的，属于开卷考试；换成自然问法，检索只找到三分之一。分数不假，但它测的是"照着关键词问能不能答对"，不是"真实用户问能不能答对"。

**剩余 1 条是标注争议，如实保留**：#3 问"发票能开公司抬头吗"，知识库只有电子普通发票条款、没有抬头规则。模型选择拒答转人工——保守但不算错。我把期望改成"正常回答"就能凑到 100%，但没有这么做。

分项：政策可答 7/8 · 订单查询 5/5 · 超范围拒答 4/4 · 陷阱（假命中）3/3。

最值得说的是陷阱那三条："我的快递丢了赔我钱"——知识库里"快递"能命中发货时效条款，属于**假命中**，正确行为是识破后转人工。3 条陷阱全过。

## 运行

```bash
node run-test.mjs                # 跑 20 条（result-r1/result-r2.json 是两轮原始数据）
node rescore.mjs                 # 修正标注后的离线重算

node lab/compare.mjs all 1 20    # 四组对照（104 次调用，约 4 分钟）
node lab/analyze.mjs             # 归因表：各组差值、成本、延迟
node lab/boundary.mjs all        # 规模 / 同义改写 / 库外 / 污染
node lab/rescore.mjs             # 判定器修正后重判（不重新调模型）
```

浏览器打开 `index.html` 可对话 + 可视化跑测试。核心逻辑在 `agent.mjs`，浏览器和 Node 共用同一份——页面上演示的和测试跑出数据的是同一个 agent。

`lab/` 里是实验代码：四组对照、归因分析、边界测试、重判脚本，以及全部原始数据。
