## 为什么这不是 6 个孤立的小作业

它们是一条线做下来的：

```
06 学会怎么评产品
  → 05 学会怎么调 AI 的说话方式
    → 03 把这些变成能算分的规则
      → 02 把评测用到客服机器人上（拒答策略）
        → 01 全部合成一个能上线的产品
04 是贯穿全程的提效工具
```

三条我自己定的原则：

1. **不让 AI 给自己打分。** 所有分数由规则计算，否则就是用感觉验证感觉。
2. **测试集必须埋陷阱。** 跨行、信息不足、过度包装、假命中——只测正常样本会得到虚假的高分。
3. **没做好的地方如实写。** 每个项目都有"没有修的问题"一节，改标准凑通过率的事一件没做。

## 技术细节（给工程师看）

每个项目目录下都有完整说明、可复现的测试脚本和原始数据：

```
projects/01-jd-matcher/        网页产品：证据三态防编造 + 规则评测引擎（48 次调用数据）
projects/02-faq-agent/         ReAct Agent：3 工具 + 拒答策略（20 条测试，可交互）
projects/03-eval-badcase/      评测打分器：4 规则 × 2 批独立回答 × 3 版规则迭代
projects/04-prd2wireframe/     PRD → HTML 线框图 CLI（200 行，零依赖）
projects/05-coze-resume-bot/   Coze 简历改写助手的设计资产
projects/06-competitor-teardown/ 竞品评测设计
```

复现方式（需要 Node 18+ 或 Python 3）：

```bash
cd projects/02-faq-agent && node run-test.mjs    # 跑 20 条 Agent 测试
cd projects/03-eval-badcase && node compare.mjs  # 重算三版规则得分
cd projects/04-prd2wireframe && node prd2wire.mjs examples/prd-jd-matcher.md out.html
```
