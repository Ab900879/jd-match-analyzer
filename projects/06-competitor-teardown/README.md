# 06 · 主流 AI 产品对比拆解（豆包 / 通义 / Kimi）

> **资产性质说明**：原始打分是 2026 年手工测试的记录，未随仓库开源（逐条截图含账号信息）。本目录公开**可复用的评测设计**：维度表、任务集、评分口径、结论框架。任何人按这套表可以复现同类评测。

## 评测设计

**3 个产品 × 3 类场景 × 每场景 10 个任务 = 90 次测试**，全部同一时段完成，控制模型版本波动。

| 场景 | 任务示例（每个场景 10 个） | 考察点 |
|---|---|---|
| 写作 | 周报润色、小红书文案、邮件改写、标题生成… | 语气控制、格式遵循、字数遵守 |
| 总结 | 万字长文摘要、会议记录提炼、多轮聊天归纳… | 信息保真、结构化、不遗漏关键数字 |
| 联网搜索 | 查最近发布的产品、核对某政策原文、找数据来源… | 时效性、来源标注、幻觉率 |

## 评分口径（每任务 0-2 分）

- **2 分**：结果可直接用
- **1 分**：可用但需手动修正（如格式、一两处事实错）
- **0 分**：不可用 / 编造关键信息 / 拒绝执行

## 关键口径决策（评测设计里最容易踩的坑）

1. **同一个提示词喂三个产品**，不为每个产品单独优化——测的是产品默认能力，不是调参能力。
2. **联网类任务当天完成**——搜索类结果时效衰减很快，隔周补测会让对比失效。
3. **幻觉单独计**：编造来源链接的联网回答，不管内容多流畅直接 0 分。

## 结论框架：按任务选工具，不存在全能冠军

三个产品在不同场景各有明显强弱项（这正是评测的价值——如果一家全面胜出，说明维度设计失败了）。最终产出的是一张"任务 → 推荐工具"对照表，而不是"谁最好"的一句话结论。
