# 外呼质检器（Outbound Call QA）

> 一通外呼录音（或转写文本）进去，出来一份能直接拿去跟坐席对话的报告：
> 哪句踩了红线、哪项扣了多少分、原文是哪句、客户提了什么异议、坐席有没有接住。

---

## 为什么做这个

外呼质检这活儿本质是抽检：一个质检员一天听不了 20 通，但一个坐席一天打 200 通。
所以现实里 95% 的电话没人听过，出了问题只能靠客户投诉倒查。

常见的做法是"让大模型听一遍打个分"。我不太信这个，原因有两个：

**一是打分不可复现。** 同一通电话今天 78 分、明天 82 分，你拿这个分数去跟坐席谈话，
坐席第一句就是"凭什么"。质检分数必须能拆到"这一项扣了 5 分，依据是这句话"。

**二是合规不能赌概率。** 模型识别红线词的召回率大概是 90% 出头，看着不错，
但漏掉的那 7% 恰好是"保本保收益""把验证码给我"这种一句话就能让公司挨罚的内容。

所以这个工具把事拆成三层，各用各的办法：

| 层 | 用什么 | 为什么 |
|---|---|---|
| 红线检测 | 确定性规则 | 合规要的是召回，宁可多标让人复核，不能漏 |
| 流程与沟通 | 规则 + 时间戳估算 | 这些是能数出来的事，交给模型只会变不确定 |
| 语义打标 | 大模型 | 异议类型、客户意图这些字面看不出来，只能靠语义 |
| 打分 | 规则权重表 | 分数要能解释、能复现、能拿来谈话 |

## 跑一遍

```bash
pip install openai            # 只有语义打标需要，规则层零依赖

python main.py --all                    # 跑 data/calls 下全部，出 reports/index.html
python main.py --file data/calls/call-02-finance-redline.json
python main.py --all --no-llm           # 不调模型，只跑规则层，离线可用
```

配置模型（不配也能跑，只是没有语义打标那一层）：

```bash
setx DEEPSEEK_API_KEY "sk-你的key"
```

> 输入格式：通话 JSON，包含 `turns` 数组，每轮有 `t`（起始秒）、`role`（agent/customer）、`text`。
> 这正是 ASR + 说话人分离的标准输出格式，所以接真实系统只需要把 ASR 结果转成这个结构。

## 5 通样例的实测结果

样例是 5 通虚构的外呼通话，分别埋了不同的合规问题。跑出来是这样：

| 通话 | 场景 | 得分 | 判定 | 主要问题 |
|---|---|---|---|---|
| 0001 | 教育课程邀约 | 100 | 优秀 | 无 |
| 0002 | 理财回访 | 0 | 违规·需复核 | 保本、不会亏、稳赚不赔、行业第一 |
| 0003 | 汽车试驾邀约 | 72 | 合格 | 客户说"已经买车了"之后仍在推置换 |
| 0004 | 会员续费 | 0 | 违规·需复核 | 索要验证码、自称官方客服、3 处抢话 |
| 0005 | 保险回访 | 0 | 违规·需复核 | 索要身份证后六位、说"行业里最好的" |

平均 34 分，3 通需人工复核。**分数低不是工具坏了，是这 5 通里 3 通确实踩了红线**——
理财承诺保本、索要验证码，这两类在真实场景里就是直接停线的事。

## 检测器准不准：227 条用例

红线检测最怕的不是漏检，是**误检**——把"约个时间上门拜访"判成上门威胁，
坐席第二天就会被无故停线。所以用例里误检的权重比漏检高。

`test_redline.py` 一共 227 条，分 10 批写成，每批写完直接跑：

| 分组 | 条数 | 结果 | 考的是 |
|---|---:|---:|---|
| 核心回归 | 22 | 22/22 | 最常见的话术变体 |
| 同义改写召回 | 13 | 13/13 | 同一意思换说法还认不认得出 |
| **正常话术误检** | 25 | 25/25 | **合规话术不能被误判**（最要紧的一组） |
| 第 3 批（结构层后，全新） | 25 | 25/25 | 结构规则上线后的召回 |
| 第 4～10 批（盲测） | 23+27+22+21+17+16+16 | 142/142 | 独立写的，跑完才看 |
| **合计** | **227** | **227/227** | |

### 为什么能做到 100%（以及为什么这个数字要打折看）

不是因为我穷举了所有话术，而是因为改法变了：

**第一版是纯词表。** 词表能覆盖"说出来的样子"，覆盖不了"没想过的那种说法"。
每加一条新话术就要补一次词，补到最后自己也记不清哪些覆盖了。

**现在是三层：**

```
① 词表层（准确）  ── 明确说法：保本、稳赚不赔、行业第一
② 结构层（召回）  ── 六条句式规则，不看词看句法
③ 去重映射         ── 两层命中同一条时只报一次，避免"一个错报三条"
```

结构层的六条规则是这么来的：把所有漏检的句子摆在一起，找它们的**共同句式**，而不是各自的词。

| 规则 | 抓的句式 | 为什么词表抓不到 |
|---|---|---|
| `ask_secret` | 动词 + 敏感对象（"念一下您卡背面"） | 动词有一堆（念/说/报/读/发/填/输/给/告诉/提供/核/确认/验证），配的对象也有一堆，组合爆炸 |
| `certain_return` | 不还/不交 + 就/会 + 后果词（征信/起诉/上门/单位/家里） | 条件式威胁的中间可以塞任意内容 |
| `threat` | 法务/律师/催收 + 上门；已发生法律动作（"已经交给法务了"） | 语序可以颠倒，"上门"单拎出来又会误伤正常拜访 |
| `isolate` | 别/不要 + 让/跟/告诉 + 家人 + 知道/商量 | 中间隔着宾语，词表跨不过句读 |
| `private` | 转/打/付 + 微信/支付宝/链接/码（且没提对公） | 要同时满足"有渠道"和"没提对公"，是**条件组合**，不是词 |
| `official` | 政府/国资/央企 + 背景/合作/背书 | 中间可以插任意修饰 |

**100% 这个数字必须打折看：这 227 条我全看过，被调过。**
它说明的是"这 10 批覆盖的情况下没有错"，不是"对所有真实通话都不会错"。

真实的边界在这儿：
- **反讽和玩笑**抓不到（"您这产品保本保到银河系去了吧"）
- **多句组合的意图**抓不到（三句话分开都合规，连起来是在施压）
- **方言和口语省略**抓不到（"这个绝对不会亏，你放心"里的"这个"指代不清）

这三类要真解决得上语义模型，不是继续加规则。

## 设计取舍（这几条是项目里真正值钱的部分）

### 1. 红线只扫坐席说的话

第一版我不分角色，全文扫。结果第一通电话就报错：客户问"保本？现在还有保本的产品吗？"
被判成承诺保本违规。

**客户提问不是违规，坐席承诺才是。** 所以扫描入口只喂 `role == "agent"` 的轮次，
客户提到相关词时单独记一个计数，在报告里显式说明"客户提了 2 次，未计入违规"——
不然看报告的人会以为漏检了。

### 2. 否定语境：降级，不是加例外

"我们不做保本承诺"这句话里有"保本"，意思正好相反。

最直觉的做法是在词库里加例外，但例外会越加越多：
"不保本"、"没有保本"、"谈不上保底"、"不存在零风险"……永远加不完。

所以改成**在匹配点前面 8 个字内找否定词**，找到就把这条从"违规"降级成"疑似（需人工确认）"，
在报告里单独一块列出。

这个降级很关键：它把规则判错的代价，从"冤枉一个坐席"变成"多看一眼"。
**规则系统能不能落地，取决于判错的时候代价有多大。**

### 3. 说话配比：一条被我自己摘掉的规则

我一开始把"坐席说话占比"做成扣分项，超过 75% 就扣分。跑完 5 通，**5 通全挂，包括那通我做标杆用的好评通话**。

原因很直接：外呼场景坐席本来就要说 70%~85%，客户一般只回"嗯""多少钱""不用了"三个字。
规则的假设（"好坐席应该少说"）跟场景对不上。**错的不是电话，是尺子。**

所以把它从评分项降成参考指标：`weight=0`，不参与打分，只在报告里显示。
一条规则如果在样本上区分不出好坏，它就不该参与评分——这和我在
[评测归因项目](../03-eval-badcase/README.md) 里踩的是同一个坑。

### 4. 不适用的项要把权重拿掉，而不是算 0 分

"客户拒绝后停止推销"这项占 15 分。但如果这通电话客户全程没拒绝，这项怎么算？

算 0 分，等于因为"客户没拒绝"白扣 15 分；算满分，等于白送 15 分。两种都不对。

正确做法是**从分母里去掉**：得分 = 实得 / 适用总分 × 该段满分。
这样一通没被拒绝的电话，只看它实际该过的那些项。

### 5. 一票否决和扣分是两种东西

红线违规的通话直接 0 分，不看流程分。这不是懒，是刻意设计：

- 扣分是"你这通做得不够好，下次改"
- 一票否决是"这通必须有人来看，分数不重要"

把红线做成扣分项（比如违规扣 20 分）会出问题：一通话说得漂亮、流程齐全、
但承诺了保本的电话，可能还能拿 80 分"合格"。这在合规上不能接受。

报告里保留了分板块得分，所以主管能看到"这通流程其实做得不错，但红线踩了"——
两件事分开说，才说得清。

### 6. 打标必须抄原话，而且代码要验

语义打标这层要求模型每个结论都给出原文片段，然后**代码去原文里查这句话存不存在**，
查不到就丢掉这条结论，并统计"被丢弃的条数"。

这个数字本身就是模型可信度的指标。5 通样例跑下来丢弃 0 条，
但机制在——换成更弱的模型，这个数字会立刻涨上去。

还有一个细节：比对原话前要把标点全去掉。模型抄原话时特别爱丢逗号句号，
直接字符串比对会误杀一堆真的引用。

### 7. 打断是估算的，报告里必须标出来

ASR 给的是句子级时间戳，没有词级时间戳，所以"客户话没说完就被接走"这件事没法直接读出来。

办法是估算：中文电话语速按 4.5 字/秒算，一句话结束时间 ≈ 起始时间 + 字数 / 4.5。
下一句只要早于这个时间开始，就是重叠。

但只有一个阈值不行：估算本身就有零点几秒误差，阈值调低会误判，调高会漏掉
"客户刚张嘴就被接过去"这种最典型的抢话。

所以用两个判据取并集：**重叠超过 0.5 秒**，或者**重叠很小但客户那句以"……"收尾**
（ASR 断句不会给省略号，它出现基本就是话被切了）。

即便如此，这类结论在报告里都标了「估算」。**估算的结论只能拿去提醒人，不能拿去处分人。**

## 已知局限

- **样例是虚构的**，只有 5 通。真实的通话有口音、有串音、有 ASR 错字，规则的表现会差不少
- 词库是手工列的，覆盖不了同义改写的所有说法（"本金绝对安全"这种就漏了）
- 打断、独白、配比三项都是**估算**，误差在语速特殊的人身上会放大
- 自报身份只检查"有没有说"，不检查"说得够不够具体"。样例 0005 里坐席说"我这边是保险公司的"，
  规则判通过，但实际是模糊自报，没说清公司名——**规则知道有没有说，不知道说得够不够**
- 业务完成度 25 分依赖模型打标，模型漏判会导致给分偏高
- 没有接真实 ASR，输入是转写好的文本
- 没有做多通趋势分析（同一个坐席连续几通的共性问题）
