## 这套项目怎么长出来的

不是 6 个孤立 demo，而是一条能力链：

```
06 竞品拆解（学会怎么评产品）
   → 05 Coze 助手（学会调 Prompt：迁移可以、升级不行）
      → 03 评测与归因（把"感觉不好"变成规则打分）
         → 02 FAQ Agent（把评测用到 Agent 上：拒答策略）
            → 01 JD 匹配诊断器（全部能力合成一个完整产品）
04 PRD 转线框图（贯穿全程：需求变了，产物重渲染）
```

## 贯穿所有项目的三个原则

1. **不让模型自评。** 所有分数由规则计算：数字必须可追溯、拒答必须双向正确、格式硬校验。
2. **评测集必须埋陷阱。** 假命中、信息不足、过度包装、严重错配——只测正常样本会得到虚假的高分。
3. **争议如实记录。** 每个项目都有"没有修的问题"一节：标注比模型乐观的样本、故意不修防过拟合的规则。改标注凑通过率的事，一件都没做。
